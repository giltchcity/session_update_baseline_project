## 2. 这份补丁实际改了什么

### 同一帧的两路新增先合并，再插入一次

原 `TrackedGaME._add_gaussians()` 先执行普通 GaME 播种，再用插入后的实际透明度探测前方新表面，同时沿用插入前的 `explained`。同一像素可能进入两次插入。

现在普通候选与 `_front_of_carried_mask()` 都读取插入前的模型，取并集、应用现有排除规则，只调用一次反投影、下采样与 `add_points`。日志增加 `game_px/front_px/overlap_px`。这修复同帧重复路径；不声称已经解决所有跨帧重叠新增。

### 冻结和承载行显式退出 densify 候选

clone/split 不再只依赖累计梯度。两者都排除 `frozen/carried`，并仅在合格候选中做容量限制排序。冻结、继承、恢复时清这些行的 `xyz_gradient_accum/denom/max_radii2D`。承载行只清几何和透明度的 Adam 状态，保留原有颜色训练。

### 独立精修恢复同一 session 上下文

checkpoint 增加两个标量字段：`session_start/support_tol`。旧文件只从已记录的 `session_starts[-1]` 恢复边界，不从行的创建时间猜测。timed checkpoint 缺少可靠边界时，精修明确报错。由此避免 `refine_only` 加载后 `carried()` 全假。

### 部分精修不再报告完整成功

`RefinementProgress` 只计已成功执行的 `optimizer.step()`。守卫和无可用帧返回 `partial`，包括 requested/completed iterations 与 stop reason。`run.py/refine_only.py` 保存可用的部分产物和报告后返回退出码3；CUDA异常记录 `failed`，保留已经保存的 pre_ref。其它后端的旧式 `None` 返回保持兼容。

split模式的 `measurement_update` 也单独写入当前session报告；部分完成时先保存必要checkpoint再停，不能进入后继session。`--resume` 检查已结束session的此项报告，拒绝跨过未完成的更新。旧checkpoint缺少该字段时保持兼容。

队列必须同时检查退出码和 `session_*/run.json` 的 `post_ref.status`、实际迭代数。只见到 post_ref 文件存在不够。部分精修仍用原 post_ref 文件名保存，是否完整以报告为准。

### 压缩比较同一种表示

新压缩的 keyframe 恢复后逐 tensor 比对；已经压缩的 keyframe 和 memory view 验证其存储表示未变。重复压缩不再把压缩字典与完整图像张量错误比较。压缩校验失败仍拒绝替换源文件；源大小在替换前记录。已全部压缩的原地调用直接返回，不写整份临时副本，也不声称重新验证过原文件的解压内容。

没有改动生产 `core/layer.py`、状态注册器、T1生存区间或评估阈值；没有给未验证的“复活”路径放行。

## 3. 真正阻塞误退的代码闭环

基点的路径是：

1. `core/layer.py::_element_rule` 用每轮最后的 on/through 给累计值加一步，超过 `ln(99)` 后丢弃该uid的证据。
2. `run.py` 合并 `element_rule/memory_object/closed_background/object_support` 后统一调用 `retire()`，后端已不知道具体原因。
3. `GameBackend.retire` 单调写入 `death_evidence`，并冻结结束行。
4. `GameBackend.elements` 仅返回 `alive_at(now)`；退出后的行无法再被同一规则投影获得支持。

行可能还保存在模型里供历史关键帧使用，但它已经从当前/未来地图与更新入口退出。直接把 `death_evidence` 清空会改变退出到恢复之间的历史可见性，也没有解决冻结状态、身份和旧state的问题。

另一个确定缺口：真实 `round_s=2.1`，合成 `round_s=10.8`，每轮却加同一个 `-log(p_miss)`。在相同p、持续through且没有支持重置的条件下，单位时间证据速率相差约5.14倍。冷启动p=.05时两步越过ln99；4.2秒与21.6秒只是该条件下的量级，不是每个对象的保证延迟。不能简单把它改成每帧加分：仓库已记录F4b在真实数据上的回归。

此外，GaME元素的normal全部为NaN，所以元素规则的60度facing保护在此后端并未生效。backend支持更新采用光轴Z和固定容差，layer采用射线range与tol+extent；全局 `pooled_sp` 又来自可靠原位物体采样，不能当作所有行的局部误差模型。

`experiments_20261005.csv` 的04:30–04:50诊断比STATUS更具体：新增结束主要落在tracked物体行，untracked行结束数为0；衣柜和转椅两个身份占新增问题的大部分。这是记录中的归因，本次没有原始checkpoint和帧可重新核实。

## 4. 下一版主修复的明确要求

只做一个观测驱动、可纠错的生命周期修改；不铺参数搜索或消融矩阵。

- **证据更新以固定的观测事件和时间戳定义。** reconciliation只负责汇总；同一事件流按2.1秒或10.8秒分组，不能改变累计语义。保留每行支持历史，避免整轮最后一票吞掉此前支持；按观测可靠性处理反证，不能把系统性读穿当独立Bernoulli样本。
- **永久结束与可逆抑制分开。** 状态关闭、明确替换等仍约束永久生命周期；元素反证先转入可投影的抑制状态，保留退出原因和state绑定。
- **先查可恢复的原表面，再决定新增。** 抑制行的查询不能依赖当前渲染alpha；同一位置、兼容身份/state、有效且可靠的新支持才可恢复。外来物体占旧位置、同身份的后继state，都不能无条件恢复旧行。
- **保持时间语义。** 若恢复属于新的有效区间，记录稀疏suppression区间/事件，使 `alive_at(t)` 保留gap；不无说明地重写旧时段。不复制整套Gaussian或optimizer来记一次恢复。
- **资源有界。** 复用已有参数，休眠索引和事件记录设明确字节上限；prune、checkpoint、跨session都保持uid绑定。达到预算时明示停止或受控淘汰，不能静默丢历史又声称历史不变。

这份候选补丁没有完成上述主修复，不能标记为F1恢复或完整robustness交付。
